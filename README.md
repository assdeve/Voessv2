# VOESS v2

Самопальный прокси на Go в стиле VLESS: TLS на порту 443, авторизация по UUID,
маскировка под обычный сайт, отпечаток TLS как у браузера. Клиент даёт локальный
SOCKS5 и проброс портов (как `ssh -L`). Сервер запускается и на VPS, и на роутере с OpenWrt (у меня лично на роутере).

> **Статус: экспериментальный.** Протокол собственный и не проходил независимый аудит.
> Может быть дырявый! На свой страх и риск!
> Гарантий обхода блокировок нет.

## Скачать (без сборки)
Готовые программы лежат на странице **[Releases](../../releases/latest)**. Выберите файл под свою систему:

| Что вам нужно | Файл |
|---|---|
| Клиент для Windows | `voess2-<версия>-windows-amd64.zip` (внутри есть `start-client.bat`) |
| Клиент для macOS (Intel / Apple Silicon) | `...-macos-amd64.tar.gz` / `...-macos-arm64.tar.gz` |
| Клиент или сервер для Linux | `...-linux-amd64.tar.gz`, `...-linux-arm64.tar.gz`, `...-linux-armv7.tar.gz` |
| Сервер на роутере OpenWrt | `voess2-router-<версия>-mipsle.tar.gz` / `mips` / `arm64` / `armv7` / `amd64` (архитектуру показывает `uname -m` на роутере) |

В каждом архиве уже лежат программа, шаблоны конфигов (`client.json`, `server.json`), документация и примеры. Контрольные суммы: `SHA256SUMS.txt`.

**Сервер на VPS одной командой** (Linux, systemd; домен с A-записью на сервер нужен заранее):
```
curl -fsSL https://github.com/ВАШ_НИК/voess/releases/latest/download/install-linux.sh | sudo sh
```
Скрипт скачает программу, создаст конфиг и UUID, установит автозапуск.

**Клиент на Windows:** распакуйте zip, откройте `client.json` в Блокноте, впишите `server` и `uuid`, запустите `start-client.bat`.

**Роутер OpenWrt:** распакуйте архив на роутере и выполните `sh install-openwrt.sh`, дальше по [OPENWRT.md](OPENWRT.md).

## Возможности
- TLS 1.2/1.3, сертификат Let's Encrypt выпускается автоматически (или свой).
- Авторизация по UUID (несколько пользователей).
- **Fallback**: браузеру и сканерам сервер показывает обычный сайт (встроенная страница, ваша папка или реальный веб-сервер).
- Отпечаток ClientHello как у Chrome / Firefox / Safari (uTLS).
- Клиент: SOCKS5 и проброс локальных портов на адреса в сети сервера.
- Сервер: список разрешённых адресов (`allow`, `home_only`), по умолчанию доступ к localhost и внутренним сетям запрещён.
- Работает на Linux, Windows, macOS, OpenWrt. Клиенту root не нужен.

## Как это работает
```
программа -> SOCKS5 / локальный порт -> [клиент VOESS] ==TLS:443==> [сервер VOESS] -> цель
```
После TLS клиент шлёт заголовок `ver | uuid | cmd | atyp | addr | port`. Если UUID неизвестен
или это не наш клиент, соединение отдаётся сайту-маскировке. Только TCP.

## Структура
```
main.go          команды genuuid / server / client
proto.go         формат заголовка, relay
server.go        сервер, сертификат, fallback, allow
client.go        клиент, SOCKS5, forwards
client_stub.go   заглушка для серверной сборки (-tags server)
config.go        конфиг
examples/        примеры конфигов и автозапуска
OPENWRT.md       установка на роутер, доступ к домашней сети
```

## Сборка из исходников
Нужны: Go >= 1.21, VPS со свободным портом 443/tcp, домен с A-записью на сервер.
```
go mod tidy
go build -o voess2 .
./voess2 genuuid                                  # UUID пользователя
```
Сервер (`examples/server.json`, впишите domain и uuid):
```
sudo ./voess2 server -c server.json
```
Клиент (`examples/client.json`):
```
./voess2 client -c client.json
curl --socks5-hostname 127.0.0.1:1080 https://ifconfig.me
```
Браузер: SOCKS5 `127.0.0.1:1080` + «Proxy DNS when using SOCKS v5».
Сборка клиента для Windows: `GOOS=windows GOARCH=amd64 go build -o voess2.exe .`

## Доступ к домашней сети и серверу
Сервер на роутере или домашней машине + `allow` и `home_only`, на клиенте `forwards`.
Примеры: `examples/server-router.json`, `examples/client-home.json`.
Подробно (OpenWrt, DDNS, файрвол, проверка): [OPENWRT.md](OPENWRT.md).

## Конфиг сервера
| Поле | Описание |
|---|---|
| `listen` | адрес и порт, по умолчанию `:443` |
| `domain` | домен для авто-сертификата |
| `cert_file`, `key_file` | свой сертификат вместо авто |
| `cert_cache` | папка для сертификатов |
| `users` | список `{name, uuid}` |
| `web_root` / `fallback_addr` | сайт-маскировка: папка или адрес веб-сервера |
| `allow` | разрешённые цели: `"192.168.1.50:22"`, `"192.168.1.0/24:*"` |
| `home_only` | `true` = разрешено только то, что в `allow` |
| `log_access` | писать адреса назначения в лог (по умолчанию выкл.) |

## Конфиг клиента
| Поле | Описание |
|---|---|
| `server` | `host:port` сервера |
| `uuid` | ваш UUID |
| `sni` | имя в TLS (по умолчанию host из `server`) |
| `socks_listen` | локальный SOCKS5, по умолчанию `127.0.0.1:1080` |
| `fingerprint` | `chrome` / `firefox` / `safari` / `go` |
| `forwards` | список `{listen, target}` |
| `insecure` | не проверять сертификат (только для тестов) |

## Ограничения
- Только TCP: нет UDP (QUIC, игры, звонки).
- Нет REALITY, мультиплексирования, CDN-транспортов.
- Новое TLS-рукопожатие на каждое соединение.
- Нет защиты от перебора и ограничения скорости.

## Безопасность
- UUID это единственный ключ: не публикуйте его и не коммитьте свои конфиги.
- Для каждого устройства заводите отдельный UUID.
- Не открывайте наружу веб-интерфейс роутера.
- Нашли уязвимость - напишите владельцу репозитория (Issues).

## Для владельца репозитория: как выпустить релиз
1. Один раз выполните локально `go mod tidy` и закоммитьте `go.mod` и `go.sum`.
2. Создайте тег и отправьте его:
   ```
   git tag v0.1.0
   git push origin v0.1.0
   ```
   (или на сайте: Releases -> Draft a new release -> новый тег `v0.1.0` -> Publish).
3. GitHub Actions сам соберёт все архивы и приложит их к релизу (вкладка Actions, 2-5 минут).
4. В `scripts/install-linux.sh` замените `OWNER/voess` на свой `ник/репозиторий`, в README - `ВАШ_НИК`.
Каждый push в `main` тоже запускает сборку, это проверка, что код компилируется.
